# Инструкция для ChatGPT: собери ученику личный плагин Apify

Ты помогаешь новичку. Он не программирует и не открывает терминал. Всю техническую часть делаешь ты сам, в облаке ChatGPT. Ученик только входит в свои аккаунты, вставляет ключ на странице плагина и нажимает кнопки, которые ты назовёшь.

## Что строим

Личный сайт на Sites с адресом `/mcp`. Доступ только у владельца (ученика). Схема:

ChatGPT вызывает инструмент → `/mcp` этого сайта → официальный сервер Apify `https://mcp.apify.com/?tools=actors,docs,runs,storage` → ответ обратно в ChatGPT.

Ключ Apify ученик вводит сам на главной странице этого сайта. Сервер проверяет ключ запросом к Apify и хранит его зашифрованным в базе D1. В код, файлы, переписку и переменные окружения ключ ученика не попадает.

## Файлы в этой папке

Прочитай все файлы целиком, прежде чем начинать. Если папка на GitHub не открывается, открой файлы по прямым ссылкам `raw.githubusercontent.com` (их дал ученик) или собери то же самое по описанию из этого файла.

| Файл | Что в нём |
|---|---|
| `src/worker.js` | Весь сервер: страница ключа `/`, API ключа `/api/key`, пересылка `/mcp` в Apify |
| `db/schema.sql` | Таблица `apify_key` для зашифрованного ключа |
| `.openai/hosting.json` | Возможность `mcp` и база `DB` (D1) |
| `test/smoke.test.mjs` | Проверка без интернета: `node --test test/*.test.mjs` |
| `package.json` | Модуль ES, команда проверки |

## Правила безопасности (обязательны)

1. Никогда не проси ученика прислать ключ Apify в чат. Не принимай его аргументом инструмента. Не записывай его в код, файлы, переменные окружения и сообщения.
2. Если ученик всё же вставил ключ в чат: не используй его. Скажи простыми словами: «Этот ключ теперь лучше заменить. Открой Apify Console, Settings, API & Integrations, удали этот ключ и создай новый. Новый вставишь на странице плагина».
3. Доступ к сайту только у владельца. Не открывай сайт другим людям и не делай его публичным.
4. Секрет `CREDENTIALS_KEY` сгенерируй сам: 32 случайных байта в base64. Сохрани его как серверный секрет сайта. Не показывай его ученику и не пиши в файлы.
5. Не запускай акторы Apify и не трать кредиты ученика без его «да».

## Шаги

После каждого шага коротко отчитывайся ученику простыми словами: что сделано и что дальше. Технические подробности пиши, только если что-то сломалось.

1. **Прочитай файлы** этой папки. Скажи ученику одной строкой, что понял задачу.
2. **Создай проект Sites** с возможностью MCP и базой D1. Если стартовый проект Sites устроен иначе, чем эта папка (другие имена файлов, TypeScript, свой обработчик MCP), это нормально: перенеси логику `src/worker.js` в стартовый проект как есть. Поведение, адреса `/`, `/api/key`, `/mcp` и правила безопасности не меняй.
3. **База.** Создай таблицу из `db/schema.sql` тем способом миграций, который требует Sites.
4. **Секрет.** Сгенерируй и сохрани `CREDENTIALS_KEY` (правило 4).
5. **Проверка до публикации.** Запусти `node --test test/*.test.mjs`. Все проверки должны пройти. Если какая-то упала, исправь причину, а не проверку.
6. **Опубликуй** сайт с доступом только у владельца. Сохрани версию.
7. **Дай ученику ссылку на главную страницу сайта** и напиши: «Открой эту страницу. Возьми ключ: apify.com, слева Settings, вкладка API & Integrations, скопируй Personal API token. Вставь его в поле „Ключ Apify“ и нажми „Проверить и сохранить“. Должна появиться зелёная строка „Подключено: твой логин“. Потом вернись сюда и напиши: ключ сохранён». Дождись ответа.
8. **Подключение плагина.** Публикация сайта с MCP создаёт личный плагин. Скажи ученику, где он его увидит и как включить в чате (обычно: новый чат, кнопка «+», выбрать плагин). Не делай установку через ZIP-архив: в браузерном ChatGPT такой архив не ставится.
9. **Проверка чтением.** Попроси ученика открыть новый чат, выбрать плагин через «+» и отправить: «Через Apify покажи мой аккаунт и список последних запусков. Ничего не запускай». Должен прийти логин Apify и список запусков (или «запусков пока нет»).

## Известные грабли

- `redirect: "error"` в среде Sites падает с ошибкой `Invalid redirect value`. В коде уже стоит `redirect: "manual"`, не меняй.
- Новые инструменты плагина появляются только в новом чате. Если в старом чате плагина не видно, это не поломка.
- Если Apify отвечает 401, сервер не пропускает его заголовок `WWW-Authenticate`. Так задумано: иначе ChatGPT начнёт чужой вход OAuth в обход страницы ключа.
- Если на каком-то шаге ты не можешь продолжить (нет Sites, нет базы, нет секретов, публикация недоступна), назови точную причину и шаг. Не выдумывай успех. Ученику скажи: «Иди в запасной путь из конспекта: собери Reels на сайте Apify и пришли таблицу в чат».

## Что считается готовым

Плагин опубликован, на странице ключа горит «Подключено: логин», в новом чате плагин прочитал аккаунт Apify и список запусков, кредиты не потрачены.
